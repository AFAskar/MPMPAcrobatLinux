# Adversarial review of the native MPMB reader and release qualification

Reviewed commit `cef6e98131b4223603ac74c6ce9783f5de6bc0af`. Hold the all-workflows release sign-off. A player can strand otherwise savable character edits in the sidebar. Independent checks also accepted wrong visible content and contradictory profile reports. The existing native and real Reader runs remain valuable evidence for their recorded workflows.

## Release blockers

1. **Read-only sidebar edits can strand the session.** The sidebar omits Field.readonly from its model and offers a text editor for every non-choice field. Once typed into, its dirty draft must commit before field selection, navigation, Save, or Save and close. A failed commit retains the draft. Retyping the original text still retries the forbidden setter. On a disposable 2024 sheet the live `Str Mod` getter returned true for readonly, and the same user-edit entry point as the sidebar returned `Read-only field Str Mod`. The navigation and save consequences follow from the UI code. Disable inappropriate editors and provide a way to cancel only the pending draft. Test an earlier valid character edit followed by a read-only selection and a successful save. [UI](../../src/ui.rs) lines 347–354, 382–411, 912–919. [Runtime](../../src/acrobat.js) lines 267–286.

2. **The promoted runtime lacks the required same-build evidence.** Gate E expressly requires applicable cases to pass on the same runtime. The local executable hashes to `716a381d1284e2a3917b6be0206043af9553b15aff7635c7b13d326d7da8b963`. Both the archived executable and Cleric profile in the eight-profile 2024 run cited by Gate A identify `59a6018c72576b830d13c03a304cfb4cbb9f48120e5dce4f0a6d29d5da804048`. The intervening cross-field Format fix directly affects appearance qualification. The subclass audit also marks its generic feature-choice responses unqualified and its individual Reader cases unrun. Separate core class sessions cannot establish every subclass-specific spell, resource and choice transition demanded by Gate C. Record a case-by-case matrix binding build, fixture, scenario, reference and captured assertions. Mark the outstanding cases pending. [Release gates](../2024-readiness.md) rows A–E. [Subclass audit](../../tools/native/subclass-audit.py) lines 152–190.

3. **A failed display qualification persists a successful profile.** Both Reader class drivers write `passed=true` before launching the paired checker. A failure or timeout adds an error and writes the success flag back in finally. I found three actual contradictory profile reports, two 2024 Cleric runs and one 2014 Paladin run. Their run IDs are 1795271463791415733, 1795272886389588159 and 1795356052260554795. Later separate comparisons can supply new evidence for these PDFs. The original reports still mislead consumers checking their top-level status. Split the intermediate state capture from terminal qualification and test failure, timeout, deferred comparison and success. [2014 driver](../../tools/native/reader-2014-classes.py) lines 414–446. [2024 driver](../../tools/native/reader-2024-classes.py) lines 406–439.

4. **The paired verifier accepts the wrong file provenance and page.** The producers record `phase.pdf_sha256` and a nested `canonical.independent.sha256`. The verifier checks an optional `canonical.input_sha256`. Hashing the current files before and after comparison only detects changes during the comparison. A two-page control with deliberately incorrect producer hashes and the same visible field on page 2 in native versus page 1 in the reference received `complete_report_pair=true`. The worker recorded both page numbers and marked the row equal. Require the producer digest and match widgets by logical page and occurrence, with an explicit mapping if generated pages need one. Add independent negative controls for each condition. [Paired verifier](../../tools/native/verify-paired-feature-displays.py) lines 43–49, 58–69.

5. **The independent readiness inspector discards class levels when checking the display.** Its Class and Levels special case removes every non-ASCII letter, including all digits. A synthetic PDF with canonical `Fighter 12` and visible `Fighter 2` returned `inspect(...)[passed] == True`. Multiclass figures can also change without changing the remaining letters. Compare class identities and their associated levels, permitting only measured formatting variations. Include a swapped-level multiclass negative control. [Inspector](../../tools/acrobat/verify.py) lines 92–110.

6. **Python optimization can turn failed readiness into accepted coverage.** Qualification relies on Python assert statements. With `PYTHONOPTIMIZE=1`, a failed 2024 report with zero cases and an old fingerprint returned a qualification record claiming 12 cases against a supplied new fingerprint. The paired and workflow verifiers also rely on assertions for acceptance. Use explicit validation errors or reject optimized execution at every relevant entry point, including subprocess workers. Run the negative controls under both interpreter settings. This demonstrates a false-pass condition. The optimization mode of historical runs was not determined. [Reference validator](../../tools/native/reference_2024_qualification.py) lines 26–50.

7. **Failure cleanup can discard the state needed to diagnose the failure.** If retaining the active PDF fails, readiness still closes the active document. The Windows close helper answers No on the save prompt. The existing cleanup unit test explicitly expects closure even when retention failed. The last on-disk run copy can therefore omit the failed interaction. When the retain result is uncertain, recover the outstanding result under desktop ownership. Surface an unresolved cleanup and block subsequent suites if the document cannot be retained safely. [Readiness cleanup](../../tools/acrobat/readiness.py) lines 48–62. [Windows close](../../tools/acrobat/windows/desktop.ps1) lines 535–549.

## Native runtime and persistence

These observations use the promoted binary. Except for the read-only case above, the controls in this section use synthetic documents. They establish native behavior. Their incidence in individual MPMB character workflows needs separate measurement.

8. **Saving rejects a settled document with calculations intentionally disabled.** A successful text edit with `app.calculate=false` and no outstanding timer was followed by a save failure, “Document calculations suspended without a resumable timer.” GUI Save and Save and close use this same readiness predicate. Track actual pending initialization/calculation work independently of the user's calculation setting. Qualify save/reopen with disabled calculations and with a genuinely outstanding class-menu callback. [Save path](../../src/ui.rs) line 409. [Readiness](../../src/acrobat.js) line 367.

9. **No-op cold saves continually enlarge the file.** Four fresh-process saves of a 1,271-byte synthetic form produced 450,654, 900,151, 1,349,649 and 1,799,146 bytes. Projection constructs a full fallback font and CID mapping on every call and serializes accumulated objects. This affects recurring character saves and increases projection work during rendering and printing. Reuse a verified matching font or embed it on first actual use. Check repeated cold saves for bounded object count and byte size alongside rendering and preservation of original resources. [PDF projection](../../src/pdf.rs) lines 657–690, 853–857, 1327–1336.

10. **Multi-select choice fields lose selection type and indices.** Input PDF selections a and c loaded as an empty string. Setting indices 0 and 1 produced the correct live array, then Save wrote a single PDF text string containing JSON and removed the selection indices. Preserve PDF arrays and selected indices through load, snapshot and projection. Verify the saved PDF object types independently and reopen it. No multi-select field was identified by the direct field-flag scan of the three original fixtures. [Field loading and projection](../../src/pdf.rs) lines 78–97, 328–346, 861–869, 926–962.

11. **Widget-specific actions collapse to the first action on the field.** In a two-widget button, activating widget index 1 ran widget zero's handler. The loader merges widget actions into one field map with first-entry precedence and activation dispatches through the common field. Retain widget action overrides indexed by widget identity and preserve field-level actions independently. Test distinct MouseUp, focus and blur handlers and the absence of a handler on one widget. A follow-up scan of active terminal widgets in the stock 2024 input did not identify a differing active handler under this rule. [PDF loader](../../src/pdf.rs) lines 228–242. [Activation](../../src/acrobat.js) lines 273–281, 304–309.

12. **PDF text decoding changes characters.** A valid single-byte PDFDocEncoding bullet (0x80) decoded to U+0080 in native; pypdf decoded the same field as U+2022. The decoder attempts UTF-8 for unmarked strings and falls back to a byte-to-codepoint mapping. Use the PDF text-string encodings with their appropriate markers and retain byte-string handling where required. Check text, field names and metadata with non-Latin-1 PDFDocEncoding characters. [Decoder](../../src/pdf.rs) lines 96–117.

13. **The timer budget drops a pending callback.** Scheduling 101 callbacks due together, advancing to their deadline, handling the budget error and advancing again produced 100 invocations. The loop deletes the 101st timer before checking the limit. Check the budget before dequeuing and distinguish resumable yielding from a failed callback. Verify that all original callbacks execute exactly once over subsequent ticks. [Timer dispatch](../../src/acrobat.js) lines 312–318.

## Host boundaries and operations

14. **Import size limits take effect after host allocation.** Both JavaScript import and XFDF import read the entire file into Rust memory before checking their advertised 16 MiB and 64 MiB limits. The QuickJS heap limit does not bound these allocations. Read at most the limit plus one byte and reject excess input before conversion. Check the actual byte count even if metadata is available. This is a source finding. No memory-exhaustion test was performed. [Native import callbacks](../../src/runtime.rs) lines 319–322 and 589–593.

15. **The desktop executable assumes trusted input.** Document scripts can supply a path to the file bridge without the interactive picker. JavaScript evaluation runs synchronously in the UI process, and runtime setup limits memory and stack but provides no execution interrupt. A faulty script can leave the UI unable to save. The project's trust limitation is already disclosed. Keep it visible in release claims, isolate document access to user-approved inputs before broad distribution, and make runaway execution interruptible. This assessment is from source inspection. [Runtime](../../src/runtime.rs) lines 243–254, 558–595. [Documented trust scope](../native-reader.md).
